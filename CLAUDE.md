# EASIFEM cookbook

Knowledge base for developing and using EASIFEM: recipes, theory notes,
and a generated API index. Public repository. Library repos are siblings
of this one (`../base`, `../classes`, `../elasticity`, `../seepage`,
`../diffusion`).

## Layout

- `INDEX.md` — one line per recipe or theory note; update it when adding,
  renaming or removing an entry.
- `recipes/` — how-tos by topic (`<topic>.md`, lowercase, hyphenated).
- `theory/` — mathematics and its mapping to EASIFEM classes.
- `api-index/` — generated by `scripts/gen_api_index.py`; git-ignored,
  never edit by hand. Regenerate:
  `python3 scripts/gen_api_index.py --repo ../classes`.
- `scripts/` — generator and other helper scripts.

## Rules for entries

- Entries are hints. Before relying on a detail (argument names, call
  order, numbering), check the current code or tests in the library repo.
- Build entries only from current code, examples and tests, and from what
  the user explains. Do not use old website pages (`docs/pages/`).
- Link sources inline with repo-relative paths, e.g.
  `classes:src/modules/FEDOF/examples/GetFaceDOF_test_1.F90`.
- Code snippets follow the `easifem-conventions` style (one `USE` item per
  line, sorted; kinds from `GlobalData`; `CALL OK(...)` checks).
- If an entry disagrees with the code, fix the entry and tell the user in
  one line.
- Keep entries short: purpose, classes involved, steps, example file,
  pitfalls. Wrap lines at 78 characters.
- Public repository: no local paths, personal notes or unpublished results.

## Version control (jj)

- This repo uses jj, colocated with git. Use `jj` commands, not `git`
  (`jj st`, `jj diff`, `jj log`).
- Describe or commit only when the user asks (`jj describe -m`,
  `jj new`). Never push (`jj git push`) without the user's explicit
  request.
- Do not edit the library repos from here; this repo only reads them.
